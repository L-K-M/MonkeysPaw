# Portable prompt content fixtures

The Swift `PromptConformanceTests` and Kotlin `EveryFixtureTest` both
semantically consume every case and visible file in all ten categories.
From the repository root:

```sh
swift test --filter PromptConformanceTests
android/gradlew -p android --max-workers=2 :core:test
# Run only the Kotlin full-corpus gate:
android/gradlew -p android --max-workers=2 :core:test --tests '*EveryFixtureTest'
# Android CI gate, including lint, R8 and both APKs:
android/gradlew -p android --max-workers=2 :core:test testDebugUnitTest \
    lintDebug assembleDebug assembleRelease
```

On the Paseo host use `/home/paseo/.local/bin/swift64` for Swift, and set
`JAVA_HOME=/opt/java/openjdk`, `ANDROID_HOME=/home/paseo/Android/Sdk` and
`MONKEYSPAW_GOOGLE_MAVEN_URL=https://redirector.gvt1.com/edgedl/android/maven2/`
for Gradle, which reads the Maven override from the environment.
`--max-workers=2` limits Gradle parallelism on this shared host.
From `android/`, the equivalent Kotlin command is
`./gradlew --max-workers=2 :core:test`. Gradle supplies absolute fixture/schema
paths from its root project and tracks both directories as test inputs;
neither is copied into resources or packaged in the app.

The Kotlin full gate reuses the category tests' semantic adapters. Content
checks cover metadata, tokens, first-use fields, ordered issues, rendering,
write eligibility and canonical YAML bytes. Canonical checks cover stored
bytes/body, hashes, favourite extraction, warning order, typed refusals,
idempotence and symmetric adoption. Import checks cover exact conversions,
native copies, reports and refusals, without executing templates, tools,
environment or file references. Path checks compare normalized path/key bytes
or the exact first issue and nullable segment. Ranking checks compare path
bytes and order, matched fields and scores with absolute `1e-12` tolerance;
usage histories retain their last 1,024 events in recording order.
LLM checks compare exact schema and recovered-object bytes, strict JSON
validity, typed artifacts with ordered draft issues, and typed reviews with
exact UTF-8 quote ranges. Merge checks compare canonical candidate bytes,
identity, ordered issues and typed preserved metadata with key presence.
Exchange checks execute the clients and compare raw
HTTP body bytes, exact headers, fixed deadlines, typed errors/pages and usage.
Both structural inventory and semantic consumption
cover the same ten categories.

All 54 DTO contracts have typed codecs and accepted/rejected coverage. Every
case checks decoding against the independent offline schema validator,
including every `x-` rule. Accepted cases also compare canonical JSON bytes,
error HTTP status and Retry-After header values. Constructed-invalid values
fail encoding, including nested contracts and cross-field relations. No
pending or stub adapters remain, and no golden is changed to fit Kotlin.

`fixtures/` contains ten content categories: `format`, `grammar`,
`render`, `validation`, `ranking`, `import`, `paths`, `canonical`, `dto` and
`llm`, plus the delegated `sync` category. Each consumer enumerates its
directories and files, rejects unknown
categories, files, schema versions and case members, and requires every
input and expectation to be consumed once. Symlinks and
unexpected nested directories are rejected. The corpus itself is the
enumeration; there is no hand-selected case list.

The original four categories keep their UTF-8 `<case>.md` input and matching
`<case>.json` expectation. Each JSON uses this dispatch envelope:

```json
{
  "schema": 1,
  "category": "render",
  "filename": "Example.md",
  "values": {"name": "Ada"},
  "builtins": {"date": "2026-10-09"},
  "expected": {}
}
```

`filename` supplies the title fallback. `values` and `builtins` are optional
string maps; builtin keys are only `clipboard`, `date`, `time`. An optional
positive integer `repeat` repeats the entire input before parsing, allowing
small deterministic source files to cover the 256 KiB UTF-8 boundary.
Expectations are specification data, never generated by the Core writer.

| Category | Required expectation members |
|---|---|
| `format` | `metadata`, byte-exact `body`, `issues`, byte-exact `canonical` (null when writing is blocked) |
| `grammar` | `tokens`, first-use `names`, effective `fields`, `issues` |
| `render` | effective `fields`, first-use `builtins`, `issues`, `result` |
| `validation` | `issues`, fail-closed `private`, effective `fields`, `canRender`, `readOnly`, `canWrite` |
| `ranking` | ordered `results`, each with byte-exact `path`, numeric `score`, and ordered `matchedFields` |
| `import` | byte-exact converted `source` and `body`, ordered `mappings`, `preservedKeys`, `dropped`, `warnings`; or a typed `refusal` |
| `paths` | byte-exact NFC `path` and `path_key`, or a typed `issue` with `code` and nullable `segment` |
| `canonical` | byte-exact stored `bytes` and `body`, `canonicalHash`, nullable extracted `favorite`, ordered `warnings`; or a typed `error` |
| `dto` | `valid` boolean; accepted error envelopes also require `http_status`, accepted Retry-After values require `header_value` |
| `llm` | exact schema bytes; or recovered object bytes/null, JSON validity, typed artifact with ordered issues, typed review with exact quote ranges, or `invalidOutput`; or canonical merge candidate bytes, identity, issues and typed preserved metadata, or a typed failure; or exchange request bytes, typed responses/errors/pages, capability formats, cumulative writes and persisted cache bytes |

A ranking case is a directory `ranking/<case>/` containing exactly one
`case.json` and its referenced UTF-8 Markdown sources. Its envelope is:

```json
{
  "schema": 1,
  "category": "ranking",
  "query": "n",
  "now": "2026-10-11T12:00:00Z",
  "prompts": [
    {"source": "example.md", "path": "Notes/Example.md", "uses": []}
  ],
  "expected": {
    "results": [
      {"path": "Notes/Example.md", "score": 4, "matchedFields": ["title"]}
    ]
  }
}
```

Here `example.md` contains front matter `title: n` and an empty body.
All envelope members shown are required; no additional members are allowed
at any level. `source` is a basename in that case directory, referenced
exactly once. No other files are allowed, including orphan `.md` files or
additional JSON files. `path` is a valid library-relative prompt path; it
supplies the folder and filename fallback, independently of the source's
physical filename. `prompts` must be nonempty, and prompt paths and
identities must be unique. Paths compare as exact UTF-8 bytes, and an idless
prompt's identity hashes those raw bytes (§5.2), so canonically equivalent
but byte-distinct paths are distinct prompts; never normalize them. Source names can stay ASCII while paths and
titles represent canonically equivalent,
byte-distinct spellings, even on filesystems that normalize filenames.
Ranking sources must parse as renderable prompts.

`now` and every `uses` timestamp use the exact ISO-8601 UTC form
`YYYY-MM-DDTHH:mm:ssZ`, with seconds and no fractional part. `uses` is the
complete history in recording order, which can differ from timestamp order
after a backwards clock adjustment. Retain its last **1,024** events before
ranking, just as `UsageStore` does. The Swift consumer records these explicit
times through an in-memory `UsageStore` and calls the same internal pure
`PromptRanking.rank` used by `PromptIndex.search`; neither reads a system
clock. The Kotlin consumer must apply the same retention and §5.4 formulas.

Result paths and order are compared by exact UTF-8 bytes. Scores use an
**absolute tolerance of `1e-12`**, without rounding or relative tolerance;
ordering never uses this tolerance. Equal scores break ties in this order:
for empty queries only, favourites before non-favourites; then the
unnormalized stored title bytes; then path bytes, both in ascending UTF-8
order. Nonempty queries apply the favourite only as the 1.5 score multiplier. `matchedFields` uses
the declared order `title`, `tags`, `folder`, `description`, `body`, with no
repeats. All terms must match; each takes its highest weighted field, then
those scores are
averaged. Exact `#tag` filters add no score and include `tags` in the matched
fields; filters alone use base match 1. Empty queries have no matched fields.
Unicode case folding followed by NFC preserves accents (§5.4).

Query separators are extended grapheme clusters whose first scalar has the
Unicode `White_Space` property, including NBSP. Swift reads stdlib
`Unicode.Scalar.Properties.isWhitespace` and discards the whole cluster.
Word-start boundaries follow scalars outside Unicode general categories
`L*`, `M*`, `N*`, read from stdlib `Unicode.Scalar.Properties.generalCategory`,
including marks and all number categories. These properties are pinned to
Unicode 17: generated additions bridge supported Swift runtimes' Unicode 15/16 data, and
private-use scalars are non-word on every platform. Changed Extend/SpacingMark/Prepend/Other
scalars are projected to known representatives only while finding separator
and standalone-`#` boundaries; the tokens retain their original scalars.
Kotlin uses the pinned ICU4J 78.3 Unicode 17 properties and grapheme iterator.

Search uses explicit full default Unicode 17 C/F folding followed by NFC
(F6). Search and sync reuse the frozen mapping data but retain separate
functions. NFC follows [Unicode 17 UAX #15](https://www.unicode.org/reports/tr15/tr15-57.html):
recursive canonical decomposition, stable ordering by canonical combining
class, then unblocked canonical composition with algorithmic Hangul. Swift's
generated NFC tables and Kotlin's pinned ICU implementation agree on that
definition. Foundation's fold/word tables vary between Darwin and corelibs;
its NFC path can misorder Tibetan marks, drop expanding marks and overrun
valid Hangul composition endpoints. None defines the search contract.
Normalized tag keys compare exact scalars, avoiding implicit host-version
normalization in Swift `String` equality. Original title/path tie-breaks
continue to compare exact UTF-8 bytes.

Regenerate Swift's attributed NFC/property data with
`python3 scripts/generate-search-unicode.py --ucd-dir <directory>`; `--check`
compares without writing. The generator verifies SHA-256 values for Unicode
17 `UnicodeData.txt`, `DerivedNormalizationProps.txt`,
`auxiliary/GraphemeBreakProperty.txt`, and Unicode 15's `UnicodeData.txt` and
`auxiliary/GraphemeBreakProperty.txt` (save the latter two with `15` before
`.txt`). No runtime download is used. The 16 added Unicode cases below are
specification expectations; the historical `unicode-foundation-*` names now
pin corrections to those platform quirks. All 20 baseline cases are unchanged.

Metadata includes nullable `id`/`description`, `title`, `tags`, `favorite`,
`private`, `format` and ordered field `declarations`. Format integers are
represented by exact decimal strings in expectations, including future
versions beyond a machine-word integer. A field includes `name`,
`type`, `label`, nullable `description`, `default`, ordered `{label,value}`
`options`, `optional`, `remember`, and `implicit`. Effective fields exclude
builtin and deferred reserved names. Tokens have `kind`: `literal` with
`text`, `placeholder` with `name`, or `escape` (emits `{{`). Issues are ordered
`{code,severity}` pairs; user copy and source locations are tested in Swift.

A render result is `{text}` or `{error}` with a typed discriminator:
`invalid_prompt`, `unsupported_format` with decimal-string `version`,
`required_value_missing`/`choice_value_invalid` with `field`, or
`builtin_missing` with `name`. Supplied snapshots and values are raw strings.
No test reads a system clipboard or clock.

The §5 clarifications are pinned here: ASCII names; next-closer grammar with
no nesting; exact `\{{` escapes; required means nonempty without trimming;
omitted choice default means no prefill, while an explicit default must be
an option; inferred deferred names are errors; lower-case YAML booleans;
recursive common Core-schema scalars with quoted literal equivalents; typed
unique mapping keys. Canonical writing keeps optional key presence and
nested ordering, normalizes scalar presentation, and never assigns an id.
Front-matter comments are not preserved. Markdown body bytes are preserved.

M3 adds `import` as the sixth category because the strict content dispatcher
cannot accept additional directories or `.prompt`/`.prompty` sources in the
original categories. It reuses ranking's case-directory shape:
`import/<case>/` contains exactly `case.json` and the one source it references.
`PromptConformanceTests` delegates this category to `ImportFixtureCorpus`;
`ImportConformanceTests` independently exercises enumeration and malformed
corpus rejection. Both consume every file, rejecting symlinks, nested
directories, orphan sources, unknown members/discriminators, and unknown or
boolean schema versions.

```json
{
  "schema": 1,
  "category": "import",
  "source": "example.prompt",
  "expected": {
    "source": "---\nfields:\n  name:\n    type: text\ninput:\n  schema:\n    name: string\n---\n{{name}}\n",
    "body": "{{name}}\n",
    "mappings": [
      {"sourceKey": "input.schema.name", "fieldName": "name", "kind": "text", "defaultSource": null}
    ],
    "preservedKeys": ["input"],
    "dropped": ["frontMatterPresentation"],
    "warnings": []
  }
}
```

`source` is a basename ending in lowercase `.md`, `.prompt`, or `.prompty`;
extension matching is case-sensitive. Dot-files, including `.DS_Store` and
`._*` metadata, are ignored at every corpus directory level. Optional
positive integer `repeat` covers the source-byte limit with a small input;
expanded fixture input is bounded to 262,145 bytes. All other envelope and
expectation members are required, with no extra members. `defaultSource` is
the original metadata property's path or null. Warning objects use `code`
and `key` for input/native-validation warnings, or `code`, `format`, and
zero-based, body-relative UTF-8 `byteOffset` for `unsupportedTemplate`. A refusal instead
uses only `expected.refusal`, containing `code` (`invalidPrompt`,
`fileTooLarge`, or `convertedTooLarge`) and ordered native issue `issues`.
Golden source/body expectations are handwritten specification data.
Input warnings follow declaration order, then native validation warnings
follow codec order, then unsupported template warnings follow byte offset.
Supported `{{name}}` placeholders count as field usage even beside unsupported
constructs. A field referenced only by unsupported expressions receives
`validation` `field.unused`; usage analysis does not fail closed for the body.

The §5.5 mapping table is portable:

| Imported source | Result |
|---|---|
| `.md` | Validate and copy all bytes, retaining comments and an absent id. A duplicate supplied ULID is replaced by the service, leaving body bytes unchanged. |
| Dotprompt Picoschema `name: string[, description]` | Text field; `name?` is optional. |
| Dotprompt `name(enum[, description]): [strings]` | Choice field with those options. |
| Dotprompt string declaration / JSON Schema object property (`type: object` or a `properties` mapping without `type`, as Dotprompt's parser reads it) | Text or string-enum choice field; preserve string description/default; fall back to `input.default.<name>`. An `input` without a supported `schema` receives `unsupportedInput` with key `input.schema`; absent `input` is silent. |
| Prompty v1 keyed/list `inputs` with `type: string` | Text or string-enum choice field; preserve string description/default; `required: false` maps to `optional: true`, while omitted `required` or `required: true` stays required. Fall back to input-local `sample`, then top-level `sample.<name>`. Valid explicit defaults, including empty strings, take precedence. |
| Prompty sample-only body placeholder | Its implicit text field gains the string sample as its default. Unsupported explicit inputs and unused sample keys remain metadata. |
| Invalid explicit default with a usable fallback | Warn with `invalidDefault` at the declaration key, keep the field with the validated string fallback, and set `defaultSource` to its metadata path. A choice fallback must be an enum member. |
| Unsupported types, invalid defaults without a usable fallback, invalid enum options, reserved/invalid names, duplicate mapped names, existing native declarations | Preserve metadata without mapping; typed warnings explain why. Builtins and deferred reserved names follow §5.3. |
| All original metadata, including `input`/`inputs`, sample, model, output(s), tools, authors | Preserve original keys and values alongside generated native fields. |
| Body | Exact UTF-8 bytes; unsupported closed expressions and Jinja2 blocks/comments remain literal and receive warnings. |

Foreign front matter uses the canonical native writer. Every converted
header reports `frontMatterPresentation`, even when the source had no
comments or styles to lose. Native YAML portability,
metadata validation and prompt-size limits apply. No provider, tool,
environment expansion, file-reference expansion or template engine executes.
The mapper reads no filesystem, clipboard, clock or entropy; the service
supplies source bytes and makes identity/publication decisions.

M5 S3 adds sync paths in `paths/<case>/`. `SyncPathConformanceTests` owns
their strict consumer; `PromptConformanceTests` dispatches this category to
it and accounts for every returned file. Each case contains exactly
`case.json` and `path.txt`, with this envelope:

```json
{
  "schema": 1,
  "category": "paths",
  "source": "path.txt",
  "scope": "user",
  "expected": {"path": "Notes/Hello.md", "path_key": "notes/hello.md"}
}
```

`path.txt` is the exact UTF-8 input, without an added newline or BOM
transformation. It can be empty or contain forbidden characters for a
rejection case. `scope` is exactly `user` (private) or `group`. An invalid
expectation has only `issue`, for example
`{"issue":{"code":"path.segment_dot","segment":1}}`.
All shown members are required; additional members at any level, unknown
codes/scopes/schema versions, invalid types or UTF-8, symlinks, nested
directories, missing files and orphan files are rejected. Like the import
fixture convention, dot-prefixed filesystem metadata is ignored at the
category and case levels. Mutation tests prove strict dispatch and byte
comparison; golden values are specification data, independent of validator
output.
The category's `.gitattributes` permits the intentional terminal space in
`trailing-space-file/path.txt` during whitespace checks and disables Git EOL
normalization for `path.txt`. Its `.editorconfig` disables automatic final
newlines and trailing-whitespace removal for those inputs. The consumer
never trims them; mutation tests reject newline and whitespace drift.

`SyncPathValidator.validate(_:scope:)` is pure and returns `SyncPath.path`
in NFC plus `SyncPath.pathKey`. It leaves local `FileStorePath`,
`RelativePath`, identities and ranking unchanged: local paths still retain
and compare their original UTF-8 bytes. Sync paths follow §8.4 and §19 B4:

- Split at every ASCII slash scalar/byte, including slashes followed by
  combining marks. A leading slash is absolute and is rejected. Every
  segment is nonempty and differs from `.` and `..`; traversal is rejected
  rather than resolved. Directory segments cannot start with `.`, because
  the local library ignores dot-directories (§5.1). Dot-prefixed filenames,
  including `.md`, remain eligible locally and for sync.
- Reject backslashes, NUL and Unicode control/format characters (categories
  `Cc` and `Cf`, Foundation's `CharacterSet.controlCharacters`, as documented
  by [Apple](https://developer.apple.com/documentation/foundation/nscharacterset/controlcharacters?language=objc)
  and [corelibs Foundation](https://github.com/swiftlang/swift-corelibs-foundation/blob/main/Sources/Foundation/CharacterSet.swift)). Segments
  cannot end in ASCII `.` or space. Interior dots/spaces, leading spaces,
  other Unicode marks and ordinary punctuation remain allowed.
- Normalize to NFC before checking size: each segment is at most **255
  UTF-8 bytes**, including a filename's suffix; the whole path is at most
  **1,024 UTF-8 bytes**, including slashes. The source may be longer when
  NFC composition shortens it; NFC expansion can also cause rejection.
- Require the exact lowercase ASCII `.md` suffix before folding. Uppercase
  extensions and combining scalars after the suffix are rejected.
- Compute `path_key` as NFC → full default Unicode case fold → NFC. The
  fixed rules are the non-Turkic `C` + `F` mappings in
  [Unicode 17.0.0 CaseFolding.txt](https://www.unicode.org/Public/17.0.0/ucd/CaseFolding.txt).
  Core embeds the complete mapping, compressed into exact ranges and
  exceptions; unlisted scalars map to themselves. No current locale,
  simple lowercasing, diacritic folding or width folding is used. This pins
  `ß`/`ẞ` → `ss`, `ς`/`Σ` → `σ`, and `İ` → `i` + U+0307; dotless `ı`
  stays distinct. Cherokee folds to uppercase. Fold expansion does not
  impose another size limit on the key. The version is part of the sync
  key contract; changing it requires assessing existing stored keys.
  Attribution and redistribution terms are in [the Unicode license](../docs/licenses/UNICODE.txt).
- Reject the exact folded byte prefix `groups/` in private scope only,
  including case variants and `Groupſ/`. Group paths may use it.
  `Groups.md`, nested `Other/Groups/`, accented prefixes and `Conflicts/`
  remain allowed. Do not decode percent escapes or replace lookalike
  Unicode slashes.

NFC uses Foundation's `Any-NFC` ICU transform, which retains and orders long
combining sequences. The convenience `precomposedStringWithCanonicalMapping`
can truncate such sequences on the supported Linux runtime, and
Foundation's case-insensitive comparison folding omits some default full
folds. Sync must not inherit these limitations; local ranking is unchanged.
In `unicode-full-fold-23`, NFC changes canonical singletons such as Kelvin
sign U+212A → `K`, Angstrom sign U+212B → `Å`, and Greek oxia capitals to
their canonically equivalent spellings. Thus `expected.path` is NFC input,
rather than the raw input bytes. This is canonical normalization; fullwidth
and circled letters retain their spellings in `path`.

`SyncPathIssue` carries no input path. `segmentIndex` is zero-based and
present only for segment issues; all other issues use null. The first
failure wins: empty path, NFC normalization, absolute path, total size, then segments from
left to right (empty, dot/dot-dot, hidden directory, backslash, control, trailing dot/space,
segment size), then suffix, then the reserved prefix.

| Code | Rule |
|---|---|
| `path.empty` | Empty whole input |
| `path.normalization_failed` | The runtime could not perform the NFC transform (also checked after folding) |
| `path.absolute` | Leading ASCII slash |
| `path.too_long` | NFC path exceeds 1,024 bytes |
| `path.segment_empty` | Empty slash-separated segment |
| `path.segment_dot` | `.` or `..` segment |
| `path.segment_hidden` | Dot-prefixed directory segment ignored by the local library |
| `path.backslash` | Backslash in a segment |
| `path.control_character` | NUL, control or format scalar in a segment |
| `path.trailing_dot_or_space` | Segment ends in ASCII dot or space |
| `path.segment_too_long` | NFC segment exceeds 255 bytes |
| `path.invalid_extension` | Missing exact lowercase `.md` suffix |
| `path.reserved_groups_prefix` | Folded `groups/` in private scope |

Wire rules are pinned by §19 B2/B3/B7/B9/B10/B13/B17–B19 and the §8.3 body
definitions, with these corpus boundaries:

- IDs are uppercase Crockford ULIDs with first character 0–7; database UUIDs
  are lowercase and hyphenated. Timestamps use exact Gregorian
  `YYYY-MM-DDTHH:mm:ss.SSSZ`, years 0001–9999, rejecting offsets, leap seconds,
  invalid calendar dates and missing/excess precision.
- Prompt scopes use `user` with absent `group_id`, or `group` with a
  required ULID `group_id`; `private` is rejected as a scope wire value.
  Feed identities use `kind: user|group` and require the matching
  `user:<ULID>`/`group:<ULID>` key prefix. Private feed metadata omits group id,
  name and role; group metadata requires all three.
- `rev`, successful write/feed `seq`, and delete/move `base_rev` are positive
  Int64; PUT `base_rev` and feed head may be zero. Overflow, fractional values,
  booleans and numeric strings are rejected. The corpus pins values beyond
  2^53 and at Int64.max without floating-point conversion.
  A snapshot at head zero must be empty; every emitted item has positive seq.
- `database_id` is required and explicitly nullable on pull requests; null
  means first sync. Response database ids are required/non-null. Cursor
  values are arbitrary **nonempty opaque strings**, including `"0"`, delta
  and snapshot examples. The DTO never parses their grammar; malformed
  server cursors map to 400, expired/restarted manifests to 409
  `snapshot_expired` with affected scopes. Clients discard the incomplete
  collected pull before restarting those scopes without their cursors.
- User display name/disabled time and device last-seen/revoked times are
  required, nullable metadata. Optional request fields, warning arrays and
  issue locations are omitted when absent, never replaced with null. Admin
  display-name patches distinguish omitted/unchanged, null/clear and
  string/set via `SyncAPI.OptionalValue`; an empty admin patch is invalid.
- Every username, including login input and user/member metadata, is 1–64
  lowercase ASCII letters, digits, dots, underscores or hyphens, starting
  with a letter or digit. DTOs reject uppercase and do not normalize it.
  All password fields are capped at `Limits.maxPasswordBytes` (72 decoded
  UTF-8 bytes), preventing bcrypt truncation. New passwords require at least
  12 Unicode scalars; login/current-password inputs remain nonempty.
  Password descriptions carry `maxLength: 72` and `x-max-utf8-bytes: 72`;
  the byte annotation also rejects multi-byte inputs below the scalar cap.
- Group roles are owner/editor/viewer. HTTP invite roles are editor/viewer;
  account-only invites omit group id and role together. TTLs use seconds,
  1–604,800, with an absent TTL selecting the seven-day server default.
  Tokens are canonical unpadded base64url encodings of 32 random bytes.
  Invite objects form an exclusive `oneOf`: the closed account branch rejects
  `group_id`/`role`, while the group branch requires both. The DTO tests count
  matching branches for the invite fixtures; no extra discriminator is needed.
- Write warnings and 422 errors contain mapped Core issue codes with their
  matching severity; locations discriminate front matter/body/path with
  one-based line/column or zero-based byte/segment coordinates. Path segment
  is explicitly null for a global path issue. `prompt.id_mismatch` supplies
  the content/URL-id check. Response metadata and error envelopes reject
  password/token hashes, credentials and underlying error text.
  `path.segment` is required and nullable; invite `expires_in` is optional
  and nonnullable. Omission and null have distinct meanings at the schema boundary.
- Content strings are bounded to 262,144 decoded UTF-8 bytes, independent
  of JSON escaping; rendered schemas carry `maxLength: 262144` and
  `x-max-utf8-bytes: 262144`. Request-envelope 2 MiB and serialized-response
  16 MiB limits are transport responsibilities in later server slices. Every prompt
  path, including move, revision, conflict head and feed payloads, is nonempty
  and bounded to `Limits.maxPathBytes` (1,024 decoded UTF-8 bytes). Descriptions
  carry `minLength: 1`, `maxLength: 1024` and `x-max-utf8-bytes: 1024`.
  Full path rules and normalization stay with `SyncPathValidator`; content
  semantic validation stays with Core's content validator and produces 422.
  DTOs do not canonicalize file bytes or normalize paths.

`original` and `merged`, distinct strict UTF-8 `.txt` references. Optional
positive `originalRepeat` and `mergedRepeat` expand each source independently.
`write` and `improve` instead require `artifact`, `original`, `filename` and
`id`, using the merge kind's strict artifact and baseline contracts; originals
are strict UTF-8 `.md` files. Write has null original and a supplied valid
ULID; improve has a supplied original and null ID. Optional `originalRepeat`
(improve only) and `artifactBodyRepeat` expand the source/body. All repeats
and expanded inputs are bounded to 256 KiB + 1. Artifact cases require a
ready merge before comparison; merge validation failures stay in merge cases.

Line expectations have exactly `rows`. Artifact expectations have exactly
`frontMatter`, `body`, `placeholderWarnings`, `originalCanonical` (null for
write) and `candidate`; the last two reference separate canonical `.md`
byte goldens. Every row has `kind: "unchanged"|"removed"|"added"`, exact
`text`, one-based nullable `originalLine`/`mergedLine` and
`placeholderWarnings`. A removed row has no merged line, an added row no
original line. Each warning is exactly `{kind: "added"|"removed", name}`
or `{kind: "renamed", from, to}`. Failure expectations have only
`error: "sourceTooLarge"|"comparisonTooComplex"`.

Both consumers compare exact row text bytes and reconstruct both complete
sources, with separate canonical header/body rows for artifacts. Swift
compares decoded string UTF-8 directly rather than Foundation JSON
reserialization. Goldens pin deletion ties, unequal section line counts,
CRLF, bare CR, final-newline presence, emoji and composed/decomposed text,
first-use ordering, retained/reused names, ambiguous pairings across hunks,
escapes and invalid multiline literal exclusion. Compact boundary cases pin
256 KiB byte caps and the bounded search frontier, including the last
successful fully replaced script and the first refused one. Mutation tests
reject changed row text/line numbers, warnings, canonical bytes, typed errors,
unread nested members, unsafe/duplicate references and invalid repeats.
No UI, executor or editor selection-offset adapter is added in this slice.

Every shown member is required, and all objects are closed recursively.
`actions` is nonempty. Profiles use `anthropic` or `openaiCompatible`.
`setup.capabilityState` is null for an absent cache or a distinct `.json`/`.bin`
basename whose raw bytes initialize `provider-state.json`. One real capability
store persists across all actions in a case. Anthropic never consults or writes
capability state. Profile IDs are
UUIDs, bases are raw inputs to the production normalizer, and keys are null
or obvious fixture placeholders. Wrong-protocol refusal has direct client
coverage. No live provider, credentials or network adapter is used.

Write intents require `brief`; review requires `source`; improve requires
`source`, `instruction` and `selectedFindings`. These are distinct referenced
`.txt`, `.md`, `.txt` and `.json` basenames respectively. Selected findings use
the strict review wire shape. All three intents also require nullable effort,
a transcript of `{role, source}` turns, and nullable feedback naming `.txt`.
Roles are `user`/`assistant`; efforts are low/medium/high/xhigh/max or null.
Model-list intent has exactly `{kind: "models", afterID: string-or-null}`.

Null `budgetMs` exercises the default 300-second action or 15-second model
budget; cursor calls receive that original model deadline explicitly.
An integer supplies a shared deadline relative to the per-action anchor;
zero/negative budgets cover refusal before sending. Fixture budgets are
bounded to ±300,000 ms. Nonnegative send and receive `elapsedMs` advance the
same virtual monotonic/UTC clocks, with receive time at least send time.
The receive clock proves that a model page cannot publish after its deadline,
while an already received action response still finishes output validation.

Every frame compares method, normalized URL bytes, the exact lowercase header

GET's body is null. No decoded-object equality substitutes for body comparison.
The 143 Anthropic body goldens were captured through the unchanged Swift client

L6's 282 OpenAI POST body goldens, typed outputs and cache bytes were captured

Goldens pin sorted keys, slash/control escaping, Unicode, CRLF, no terminal

Official normalized `api.anthropic.com` alone gets beta/fallback fields.
No temperature, top_p or thinking field is added. Swift's only production
change is an internal clock seam with the same live defaults.

A reply has either `{elapsedMs, status, headers, body}` or
`{elapsedMs, failure}`. Raw `.bin` response bytes bypass UTF-8 prevalidation
and reach the production envelope decoder. Failure is a known transport code;
no raw diagnostic is stored. HTTP statuses are integers 100–599. Frames and
`requestCount` must agree, and every unexpected automatic attempt fails.
Test-transport assertion failures survive protocol error sanitization.

Exactly one of expected `output`, `page` and `error` is nonnull. Output references
the existing closed typed-result shape, including draft issues and review quote
byte ranges. Page has exactly `models: [{id, displayName}]`, `hasMore`, `firstID`
and `lastID`, with nullable names/cursors. Usage is null or nonnegative
`{inputTokens, outputTokens}`. Error has `code` alone for ordinary typed errors;
transport adds `transport`, unexpectedStop adds the synthetic `reason`,
providerFailure adds integer `status`, and rateLimited adds nullable finite
nonnegative `retryAfter` seconds. No raw reason enters client diagnostics.
Anthropic cache expectations remain `{format: "json_schema", writes: 0}`.
OpenAI cache has exactly `format`, `writes` and `state`. Format is `json_schema`,
`json_object` or `none`, inspected through a separate snapshot so assertions
cannot change the live client's observed identity. Writes count cumulative
publication attempts since setup; initial bytes do not count. State is null
for an absent file or a distinct `.json`/`.bin` byte golden for the persisted
file, including unchanged corrupt/future bytes. Every state reference is
consumed exactly once. Model listing asserts no live cache access.

OpenAI cases pin schema → object → none under one absolute deadline, at most
three POSTs, learned starts on later actions, cached object → none, profile
isolation, normalized URL/key equivalence, identity resets and corrupt/future
repair after validated lower-format success. Failed probes leave disk bytes
and write counts unchanged. Only explicit current-format or `response_format`
rejection permits a downgrade; generic/schema/auth/rate/network failures do
not. The rejection reader matches Swift's eager JSONSerialization separately
from envelope decoding, including last duplicate members, invalid unused text
and overflow numbers. First-choice-only output, refusal/tool/function/missing
stops, optional usage, model-name fallback, keyless local requests and escaped
transcript/feedback use the same typed and byte checks. Direct client tests in
both suites prove on-time output remains usable after parsing crosses the
deadline and cache IO failures retain validated output and usage.
Unicode rejection cases pin Swift Character whitespace splitting: a space or
NBSP with an attached combining mark is dropped as one whitespace character;
a tab and combining mark stay separate, so that message does not probe.

The response families pin text after thinking, concatenated text blocks, every
stop outcome before strict output parsing, malformed/empty envelopes, output
recovery and validation, optional invalid usage, one-page names/cursors,
HTTP status mapping, delta seconds and date Retry-After and one attempt on 400.
Envelope parsing follows JSONDecoder separately from strict output parsing:
it accepts an initial UTF-8 BOM, keeps the first duplicate member, ignores
unknown values including numeric overflow and retains raw string BOMs.
Envelope text decodes only when needed, so malformed unused/optional text
cannot override a stop or invalidate an otherwise valid output. Malformed
required text still fails before strict artifact/review decoding.
Strict output keeps its existing 32-container, duplicate and finite-number
rules; the envelope parser has a separate 512-container safety bound.
Mutation tests cover unknown nested members, boolean numeric fields, unsafe
references, changed request bytes/headers/deadlines, false typed goldens,
missing/orphan files and altered capability/write expectations.
