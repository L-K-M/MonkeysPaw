## 19. M4 and M5 decisions

These defaults resolve ambiguities found while planning the assistant (M4)
and the sync server (M5), the same way §17 records owner-overridable
defaults. The plan proceeds on them unless the owner says otherwise. Each
row names the slices it gates (A = assistant, S = server); a slice that
changes a contract amends the referenced section in the same PR.

| ID / gates | Ambiguity or conflict | Default |
|---|---|---|
| B1 · A1/A2 | §4.2 says drivers alone touch networking; D8/§4.6 place URLSession in Core. Literal Foundation + Yams excludes Linux's FoundationNetworking module. | Document the narrow portable URLSession-adapter exception and conditional FoundationNetworking as part of Foundation. Keep HTTPTransporting injection, platform secrets, no NIO/third-party schema library in Core, and all UI work through MainThread. |
| B2 · S1/S2 | DTOs are only sketches; schema derivation/dialect is unspecified, and Codable alone does not describe every invariant. | Define complete bodies, warning/error envelopes, nullable/omitted fields, scope unions, UUID/ULID spelling, Int64 seq/rev and UTC timestamp precision first. Use shared explicit schema/field descriptions plus encoding/decoding contract fixtures; JSON Schema 2020-12. A sample-value encoder alone cannot prove optional/enum constraints. Exact dump-schema executable is required by §10.7. |
| B3 · S1/S11/S13 | “Bodies capped at 256 KiB” conflicts with a 256 KiB content string plus JSON escaping; 8 MiB raw content can exceed the 16 MiB JSON response cap. Extra protocol failures are undefined. | Apply 256 KiB to decoded prompt UTF-8; separately cap the HTTP request envelope at 2 MiB. Budget serialized pull bytes, including metadata, and assert final ≤16 MiB. Pin 400 malformed request/cursor, 413 envelope overflow, 429 login lock and sanitized 5xx, alongside mandatory §8.3 shapes. |
| B4 · S3 | NFC-normalized may mean reject or normalize; full Unicode folding/order/extension case are unstated. Local paths intentionally remain byte-distinct. | Return an NFC path, then NFC/full case fold/NFC path_key under fixed locale rules; exact lowercase .md. Fixture sharp-s, sigma, dotted-I, decomposed accents and byte limits. Split on slash scalars/bytes. Keep local FileStorePath/RelativePath/ranking semantics unchanged. |
| B5 · S4 | §9.4 adoption compares an idless/different-ID local file with server bytes containing id; §9.5 hashes canonical stored bytes. | Keep stored canonical_hash over full canonical bytes. Adoption uses a separate identity-neutral comparison (the id key is ignored on both sides). CanonicalForm is pure and returns favorite extraction/warnings; only M6 persists per-user state. |
| B6 · S5 | §8.1 puts WAL in the first migration, but §8.6 requires transactional migrations; database pragma/durability/pool policy is unspecified. | Configure/verify WAL before transactions; migration DDL remains transactional. Set foreign_keys per connection, explicit busy timeout and synchronous=FULL; use local-disk /data and a controlled writer boundary. SQLite forbids journal-mode changes in active transactions and in-memory WAL ([SQLite PRAGMA documentation](https://www.sqlite.org/pragma.html#pragma_journal_mode)). |
| B7 · S5/S7 | login_attempts(username,ip) limits pairs, not account and IP independently. Username normalization and trusted-proxy parsing are undefined. | Separate persisted account/IP buckets; lowercase bounded ASCII usernames with one uniqueness rule and dummy bcrypt for unknown users. Parse configured IP/CIDR peers, walk XFF from trusted hops, otherwise use socket peer. Do not trust the entire network by default. |
| B8 · S7 | Backoff base/reset/window and status are unstated. | After the fifth failure use 30 seconds, doubling to 15 minutes; 429 while locked with Retry-After. Define counter decay and successful-account reset without allowing one valid login to erase IP attack history. Pin times with injected clock and restart tests. |
| B9 · S1/S6/S8 | Password/admin patch bodies, device listing/revocation behavior and bootstrap failures lack schemas. | Own change supplies current_password/new_password; reset/disable revoke as specified, preserve data. GET /me exposes only caller device metadata. Fail startup on missing/unreadable bootstrap secret when users are empty; ignore it later. CLI passwords use stdin, and secret-bearing descriptions are redacted. |
| B10 · S1/S9/S10 | No existing-account invite redemption endpoint; group_id=NULL invites have an unexplained role; membership PUT may add or only change roles. | Add POST /api/v1/groups/join {invite_token} for an authenticated existing account; auth/register remains new-account invite-only. Make account-only invite role absent and group role required. Membership PUT is explicit add/change for an existing user, with owner/admin checks. HTTP owner invites are forbidden even through admin/invites. |
| B11 · S9/S11 | Admin “no self-grant” conflicts with “any user creates a group and becomes owner”; admin ✓ for revision authors conflicts with no prompt read outside memberships. Self-demotion/owner promotion are unclear. | Creating a new group is the bounded automatic-owner exception. No self-add/elevation to an existing group, including invite redemption. Permit owner promotion and safe self-demotion with last-owner checks. Admin may inspect membership metadata globally; revision content/authors require current prompt visibility. Clarify §8.2 rather than add an admin prompt endpoint. |
| B12 · S8–S12 | Audit action/actor representation, group deletion mechanics and last-owner concurrency are unstated. | Stable action enum, actor/target IDs and time, never credentials/content. Required account/membership audit is transactional. Soft-delete groups or retain relational stubs until prompt retention runs; remove membership visibility immediately. Serialize owner checks and writes; CLI uses an explicit operator actor. |
| B13 · S1/S11/S12 | CAS creation is not the sketched UPDATE; error precedence, delete/move revs, tombstone GET and PUT scope mismatch are unspecified. /move conflict head lacks scope needed by §9.6. | Atomic INSERT for base_rev=0; authorize actual existing identity before any conflict/410 payload. Existing visible ID returns conflict, foreign ID 404; stale rev before destination clash. GET tombstone 404; write tombstone 410. Delete/move each increment rev and append a revision as “every accepted write” requires. Extend conflict head with scope/group_id; reject PUT scope change as conflict. |
| B14 · S12 | Destination owner and creator/history semantics on transfer are unspecified. | group→private targets the caller only; private→group/group→group retain created_by and set updated_by. Entering group always canonicalizes. Retain old revisions but expose destination-era revisions by default, avoiding accidental sharing of old private text; authorized tombstone history stays readable until purge; add revision-scope metadata; other destination members see only revisions written in the destination scope, while the prompt's creator keeps its earlier revisions. |
| B15 · S5/S15 | Tombstones purge after 90 days, but §8.3 promises stale IDs cannot resurrect. | Purge content/history according to retention, but retain a compact retired-ID/scope record indefinitely. Preserve authorization before exposing 410. If the product instead bounds anti-resurrection to 90 days, that is an explicit contract change, not an implementation inference. |
| B16 · S5/S12/S13 | Changes have only prompt_id/kind, while revisions omit historical scope/path and are capped at 200. Joining current head can associate moved/changed content with an old-scope event. | Store immutable change payloads, or a revision link whose required payload survives feed retention. Include scope/path/rev at the event's version; revision pruning cannot invalidate retained feed rows. Never obtain an old-scope upsert by blindly joining the current prompt head. |
| B17 · S1/S5/S14 | Separate page transactions plus current live prompts cannot produce a frozen head snapshot; revisions lack the history needed to reconstruct one. | Materialize a frozen snapshot manifest/payload keyed by database_id/scope/head, with bounded lifetime/storage; reauthorize every page. Define expired/restarted snapshot signaling so the client discards incomplete pages. No open read transaction across HTTP requests: it can obstruct WAL checkpointing ([SQLite WAL documentation](https://www.sqlite.org/wal.html)). |
| B18 · S1/S14/S15 | Quiet scope floor=head+1 makes completed snapshot cursor=head fall below floor again. “Head” could disappear if computed from retained rows only. | Keep a durable scope high-water mark (or derive it from retained max and floor−1). Amend stale-cursor test to cursor+1 < floor_seq, so a cursor at the highest purged seq is current. If exact below-floor behavior is retained, document/test repeated snapshots; never reset head/floor to zero after purge. |
| B19 · S13/S14 | 200 items per scope or response, collapse window, empty-page progress and scope fairness are undefined. A scope can move out then back in. | 200 emitted items per response, shared serialized byte budget, deterministic fair scope scheduling. Collapse only safe same-prompt runs inside the consumed interval, preserving final kind; cursor is highest consumed seq, not the last emitted item's arbitrary seq. Explicitly test move-out→move-in, empty pages and has_more. |
| B20 · S16/S17 | Generic compose exec instruction cannot safely restore a database still open by serve; file/path validation and migration compatibility are unspecified. | Stop serve; restore using a one-shot compose run, exclusive lock, integrity/schema checks, staged replacement and safe WAL handling; migrate and rotate UUID before restart. Refuse live/newer/corrupt input and occupied backup destinations. VACUUM INTO remains the online backup path. |
| B21 · S18/S19 | PUID/PGID/TZ are listed but current Dockerfile fixes a system user; TLS/proxy trust and dirty-checkout behavior are unspecified. | Fixed default UID/GID (1000), effective compose user override rejecting UID 0, documented host-directory ownership, no root runtime/chown workaround. Stored timestamps stay UTC regardless of TZ. Explicit trusted Caddy peer/network only. Update refuses dirty/diverged checkout and synchronizes without force; preserve configured or running tls before pulling only external images. |
| B22 · S21 | Prerelease X.Y alias policy, publication ordering and existing five-file release assembly are unspecified. | Prereleases get exact prerelease tag only; stable tags get X.Y.Z/X.Y/latest. Native builds may parallelize; registry promotion and GitHub undraft require all latest-tag gates. Images are registry objects, not a sixth release asset; separate OCI workflow artifacts from the existing release-asset glob. Job-scoped packages:write, no publish credentials in PR builds. |
| B23 · A1/A4/A12 | Profile IDs, env variable names, clear/delete semantics and endpoint changes are unspecified; blank=keep could send a retained key to a newly edited host. | Stable profile IDs and secret accounts, defined per-profile env override, explicit Clear/delete. Env tier is read-only for persistence. Changed kind/host requires re-entered key; Test uses only the draft's selected account. Cache key includes normalized endpoint/profile/model and invalidates on changes. Reject credentials in URL/query. |
| B24 · A6/A7/A10 | §7.1 says retries are user-only, whereas §7.2 automatically downgrades on 400. Capability state after a non-schema 400 is ambiguous. | The two format probes are the sole automatic retry exception, within one 300s action budget. Persist a rejected-format capability only after a lower-format attempt succeeds; otherwise show a typed failure. No automatic network/auth/rate-limit retry or provider fallback chain. |
| B25 · A5/A9 | Strict JSON decoding, duplicate fields, quote mismatch and schema/resource ownership lack implementation details. | One shared schema description feeds both requests and local validation; Codable's unknown-key tolerance is insufficient. Reject duplicates/invalid enums/additional properties; unmatched review quote is displayed as unmatched and never highlights unrelated text. Escape data delimiters and snapshot shipped prompts. |
| B26 · A9 | §7.3 carries other front matter “verbatim”; §5.2/current writer normalizes YAML and drops comments. | “Verbatim” means unchanged typed values/key presence/unknown nested data, subject to existing canonical serialization. If lexical preservation is wanted, change §5.2/codec first. Do not promise comment preservation. PromptCodec:84, §5.2. |
| B27 · A11 | Provenance is required but HistoryRevision:26/HistoryStore:28 have no origin or commit metadata. New prompts have no pre-save history snapshot. | Versioned app-data provenance for the current head and archived revision, origin=llm, timestamp, provider host/model and optional usage; no keys, brief, notes or transcript. Migrate/prune it with identity/history. Report a committed-file/provenance failure explicitly. Keep server revision origin a separate typed operation hint until shared provenance is specified. |
| B28 · A10/A11/A15/A16 | Which unsaved source is sent, editor changes during a call, and exact accepted-byte behavior are unspecified. | Snapshot the current validated editor buffer and revision/session/stamp at explicit action. Changed buffer/disk/graph invalidates acceptance until a new diff is shown. Preflight final canonical bytes and new-file ID before preview; Accept saves exactly that candidate through existing service checks. M3 owns the unsaved/conflict UI contract. |
| B29 · A4/A17 | M4 scans config/data and requires a saved key nowhere; D9/§12 deliberately allow a plaintext 0600 fallback there. | With Keychain or Secret Service, the scan of the repository, config, data, log and temporary directories must find zero copies of the key; separately assert the fallback exists only in the named 0600 atomic secrets file, visibly “unencrypted”, with zero other copies. Amend §15 to distinguish tiers. Removing fallback instead would require changing D9/§12. |
| B30 · A5 | §7.4 says compiled resources; current package/deb/server packaging ships executables without an Assistant resource-bundle strategy. | Use the existing seed-catalog pattern: checked-in .md prompts deterministically embedded in Swift, snapshot-tested against source. Clarify “compiled resources” accordingly. If using SwiftPM resource bundles instead, update every desktop packager/runtime path, not only Package.swift. |
| B31 · A6/A7 | Normal OpenAI stop is absent from §7.2's explicit normal list; defaults/model/beta/fallback assertions are time-sensitive. | Specify OpenAI stop as normal and every unrecognized nonempty completion as unexpectedStop. Preserve Q6 and the stated Anthropic defaults until primary API verification/owner tests establish a plan change; gate beta/fallbacks on exact normalized api.anthropic.com host, never a custom endpoint. |
| B32 · A10/A11 / M6 integration | §7.3 requires group editor/viewer behavior before M6 supplies group access state. | Provide a small Core access-state seam: viewer offers a new private copy; write/improve in group requires editor+. M4 local operation proceeds without building Account/sync UI. M6 supplies authoritative role changes and invalidates drafts; server still enforces independently. |
| B33 · A17/S18/S21 | §8/§12 require privacy disclosures, but §15 assigns full SECURITY.md/PRIVACY.md to M7; both files are absent here. | Ship minimum §12 assistant outbound/key-tier and server plaintext/operator-access/single-process/TLS/backup disclosures with M4/M5. Leave full platform documentation and polish to M7. |

Owner decision 2026-10-19 supersedes B22's registry tags, promotion and
package-write permission requirements. Both native image build/smoke gates
remain; no images are pushed to any registry. See the [current release
