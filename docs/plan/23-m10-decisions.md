## 23. M10 decisions

These defaults resolve ambiguities found while planning Android sync (M10),
as §§20–22 record owner-overridable defaults. The plan proceeds on them unless
the owner says otherwise. Each row names the slices it gates (Z = M10 Android
sync slices; Y = M6 Swift sync; K = M8 Android foundation; L = M11 assistant).
B, E, F, H and J IDs refer to the decisions in §§19–22. A slice that changes a
contract amends the referenced section in the same PR. The defaults preserve
those earlier decisions except where a row explicitly clarifies an Android
boundary. Recording a default does not claim its gated implementation or
acceptance proof is complete.

Exclusive publication and moves therefore use same-filesystem rename without replacement, serialized across store instances; reject cross-filesystem copy fallback. A consumed staging name proves applied publication for both new and replaced files. This preserves the existing cooperating-writer boundary, not protection against a malicious same-UID process. |

| P8 · Z9-Z12/Z25 | Conflict origin, lost acknowledgements and group transfers have settled details beyond §9's short prose ([E9-E20](20-m6-m8-decisions.md), push). | Persist exact sent scope/path/bytes/hash/base rev before HTTP, independently of fresh disk reads. Fixed issue + operation fingerprint suppresses unchanged 422/403/non-DELETE 404 retries. |
